一、問題現象與根因分析 (Issues & Root Causes)
--------------------------------------------------------------------------------

[Issue 1] Client 端報錯 AttributeError: 'list' object has no attribute 'values'
- 現象：GUI Client 啟動 PV 監聽時卡死或拋出例外，控制台出現 GeneratorExit 與 AttributeError。
- 根因：Caproto 1.3.0 (PyPI 正式版) 存在 Upstream Bug，內部容器 subscriptions 被宣告為 list 卻呼叫了字典專用的 .values() 方法。此外，新版 monitor 改為回傳 (event, context, data) 三元組，舊代碼存取 resp.data 導致解析失敗。

[Issue 2] Client 端連線風暴與 IOC Server 崩潰 (WinError 995)
- 現象：IOC Server 記錄到大量 Client 快速建立與切斷 TCP 連線，最後跳出 OSError: [WinError 995] 伺服器終止。
- 根因：
  1. Client 因 Issue 1 崩潰後，背景 Thread 在 while True 迴圈中無延遲（Zero-delay）重試，造成 TCP 埠連線風暴。
  2. Windows 下 asyncio (IocpProactor) 在處理 Socket 被強制關閉時，會在背景 Task 拋出 WinError 995 (ERROR_OPERATION_ABORTED)。原 IOC 的 try...except 僅包覆主執行緒同步層級，無法擷取背景 Event Loop 的未處理例外。

[Issue 3] Client 端報錯 'ControlWorker' object has no attribute '_run_async'
- 現象：pc1_control_gui.py 狀態顯示 DISCONNECTED，日誌跳出 Connection lost。
- 根因：重構為同步 Monitor 時，ControlWorker 類別中重複定義了兩個 run() 方法，後定義的舊版 run() 覆蓋了新方法，並嘗試呼叫已移除的 _run_async()。

--------------------------------------------------------------------------------
二、處置與修復方案 (Solutions & Fixes)
--------------------------------------------------------------------------------

1. IOC Server 端 (ca_server/ioc_server_pc2.py)
   - 繼續採用 caproto.server 架構（純 Python、寫法直觀）。
   - 在 asyncio Event Loop 上掛載自訂 async_exception_handler，自動過濾並忽略 Windows Socket 正常斷線引發的 WinError 995，確保 IOC 伺服器長時間穩定運作。

2. Client / GUI 端 (gui/pc1_control_gui.py & gui/pc2_status_gui.py)
   - 放棄使用 caproto 的非同步 Client (asyncio.client)，避免 Async Generator 的 Upstream 漏洞。
   - 重構為工程穩定度最高、全球各大光束線實驗室驗證多年的 PyEpics 架構（epics.PV / epics.camonitor）。
   - 由 PyEpics 底層官方 C 語言動態庫 (libca) 處理連線與監聽，徹底解決 Socket 風暴與崩潰問題。

--------------------------------------------------------------------------------
三、最佳實務架構建議 (Recommended Architecture)
--------------------------------------------------------------------------------
- Server 端：caproto.server + Windows asyncio Exception Handler（開發快速、零 C 編譯環境依賴）
- Client 端：PyEpics（底層 C 語言實現，連線極度穩定、支援動態 IP 與安全連鎖防範）
